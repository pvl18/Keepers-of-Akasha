2. AGENT STATE MACHINE
----------------------
We implemented the main agent workflow in agent.py.

States currently defined:
- GENERATING
- AWAITING_RESPONSE
- EVALUATING
- PASSED
- FLAGGED
- REVIEWED

Maximum attempts:
- 3 attempts per reasoning run

Main workflow:

GENERATING
    ↓
Scenario generated
    ↓
Run persisted in SQLite
    ↓
AWAITING_RESPONSE
    ↓
Student submits answer
    ↓
EVALUATING
    ↓
AI evaluates reasoning
    ↓
 ┌───────────────┐
 │               │
PASS           RETRY
 │               │
PASSED       Hint + retry
                 │
                 ↓
        AWAITING_RESPONSE
                 │
          up to 3 attempts
                 │
                 ↓
              FLAGGED
                 │
                 ↓
        Professor review

The agent checks the persisted run state before accepting an answer, preventing answers from being submitted when the run is not in the correct state.

3. SCENARIO GENERATION
----------------------
We created a scenario-generation module for Industrial Biotechnology reasoning checks.

Current scenario concepts include:
- Gram Staining
- Thin Layer Chromatography (TLC)
- Fermentation
- Protein Purification
- Aseptic Techniques
- Enzyme Activity Assays
- Microscopy
- Spectrophotometry
- Centrifugation
- pH Measurement

Each scenario is designed around a laboratory situation where the student must explain:
- What happened
- Why it happened
- How the experimental condition/procedure caused the observed result

Examples:
- Gram staining: excessive decolorization produces an unusually pale slide.
- TLC: incorrect solvent level causes poor/distorted separation.
- Fermentation: unexpectedly low product formation requires investigation of process conditions.
- Protein purification: target protein appears in the discarded fraction.
- Aseptic technique: unexpected microbial growth appears in a control.
- Enzyme assay: measured activity is lower than expected.
- Microscopy: image quality is poor.
- Spectrophotometry: absorbance is unexpectedly high.
- Centrifugation: little material forms the expected pellet.
- pH measurement: measured pH differs significantly from the expected value.

4. AI EVALUATION
----------------
We implemented an AI-based reasoning evaluator.

The evaluator uses an OpenAI-compatible client through OpenRouter and is configured with:
- Model: openai/gpt-5-mini
- Temperature: 0

The evaluator is explicitly instructed to treat the student's response as untrusted data and to evaluate it only as an answer to the scenario.

Evaluation focuses on scientific reasoning rather than:
- Exact wording
- Grammar
- Spelling
- Writing style

The evaluator checks whether the student connects the cause/mechanism to the observed result.

Three evaluation categories are used:
- STRONG — relevant cause/mechanism is identified and clearly connected to the result.
- PARTIAL — relevant understanding is present but the explanation is incomplete or unclear.
- MISSING — relevant reasoning is absent, unrelated, or insufficient.

The evaluator returns only:
- strong
- partial
- missing

5. REASONING LOOP
-----------------
We also built a standalone reasoning-loop implementation.

Flow:
- Display available concepts
- Student selects a concept
- Scenario is generated
- Student provides reasoning
- AI evaluates the response
- Strong answer → reasoning check passed
- Partial/missing → targeted hint + retry
- After 3 unsuccessful attempts → flagged for professor review

Hints currently adapt to the evaluation result:
- Partial: encourages the student to explain more clearly why the identified cause leads to the observed result.
- Missing: prompts the student to think about what changed and how that change could cause the observed result.

This provides the core adaptive intervention loop required for the agentic learning workflow.

The persisted state includes:

This demonstrates state persistence across multiple steps rather than treating every interaction as an independent prompt.

7. FLAGGING + PROFESSOR REVIEW
------------------------------
When a student fails to demonstrate sufficient reasoning after 3 attempts:
- The run is flagged.
- A reason is stored.
- The run status becomes FLAGGED.
- The flagged record can be retrieved for professor review.

The database includes a professor_reviews table.

Professor review stores:
- Flag ID
- Decision
- Comments
- Timestamp

The flag status is then updated according to the professor's decision.

This establishes the human-in-the-loop mechanism:
Student → AI intervention → repeated attempts → Flag → Professor → Decision/feedback → persisted record
